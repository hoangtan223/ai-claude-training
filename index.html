Myth 1 of 3
❌ Myth
"AI thinks like a human"
✅ Reality
AI predicts, it doesn't reason. It's pattern matching at enormous scale — not thinking, understanding, or feeling.

When Claude writes a sentence it's asking: "what word most plausibly comes next?" — billions of times in a row.

Myth 2 of 3
❌ Myth
"AI will replace designers"
✅ Reality
AI accelerates the work. Judgment, taste, and empathy still belong to humans. Designers who use AI will outpace those who don't.

The risk isn't AI replacing you. It's another designer using AI being 10× faster than you.

Myth 3 of 3
❌ Myth
"It's magic. It's always right."
✅ Reality
AI can be confidently wrong. It's optimised to sound right, not to be right. Always verify before presenting to a client.

Like a talented intern who sometimes makes things up without realising it.

Part 1 — LLM Fundamentals

What is an LLM?

📚

The Well-Read Intern

Imagine someone who read virtually everything ever written and became incredibly good at predicting what a helpful, coherent sentence looks like next. That's a Large Language Model.

It doesn't know things — it generates plausible responses based on patterns from training data.

✗

Doesn't "know" facts

✓

Generates plausible text

✗

Doesn't reason or feel

LLM Fundamentals

The neural network underneath

An LLM is a massive neural network — billions of simple units called neurons, organised in layers, each passing signals forward.

Neurons — simple units that receive a number, apply a weight, and pass a signal forward
Weights — the strength of each connection, learned from trillions of examples during training
Output — a probability score for every possible next word in the vocabulary

GPT-4 has ~1.8 trillion parameters (weights). Claude's aren't public — but same order of magnitude.

LLM Fundamentals

What is a token?

Tokens are the chunks LLMs actually read — roughly ¾ of a word or 4 characters. Billing is based on tokens.

Understanding AI is easier with the right mental model .
💬

Short chat

~1,000 tokens
fraction of a cent

🤖

Agent run (10 steps)

~30–100k tokens
noticeably more expensive

📄

One page of text

≈ 750 tokens
useful reference point

Cost = input tokens + output tokens (output costs more) · varies by model · prices change over time

What counts as input?
System promptset by the product, sent every time
Conversation historyevery prior message, growing
Tool definitionsagent mode only
Your current messageusually the smallest part
Output costs ~5× more per token than input — the model must generate each token one at a time, while input is read all at once.
Worked example — 1 chat message (Sonnet)
System prompt200 tokens
Your message50 tokens
Claude's reply300 tokens (output)
Input:250 ÷ 1,000,000 × $3= $0.00075
Output:300 ÷ 1,000,000 × $15= $0.0045
Total for 1 message≈ $0.005
Scale matters: 1,000 users asking one question = ~$5. An agent run with 20 steps can be 100–500× a single chat message.
LLM Fundamentals

How does "reasoning" work?

Extended Thinking

Before answering, the model generates a scratchpad of intermediate steps — "show your work in math."

🤔 "The user is asking about X..."
🤔 "I should consider A and B..."
🤔 "The best answer is therefore..."
✅ Final visible response

Each step is easier to predict than the final answer alone → better accuracy on complex tasks.

Is it actually reasoning?

  • ✓
    Generates intermediate steps before answering
  • ✓
    Significantly improves accuracy on multi-step problems
  • ✗
    Doesn't verify logical truth or catch all contradictions
  • ✗
    Can write confident-sounding reasoning that leads to wrong answers
  • ✗
    Not the same mechanism as human reasoning
Verdict: It's reasoning-shaped behaviour. Useful approximation, not an accurate description of what's happening inside.

How AI Fits in Products

Why AI loves the terminal

⌨️

What is a CLI?

A Command Line Interface — you control your computer by typing text commands instead of clicking buttons. The terminal, shell, console — all the same idea.

Why it's having a renaissance

GUIs were designed for humans. CLIs were designed for composability. AI agents are neither — they're programs that need to act. The terminal gives them full, predictable access to a machine.

Why LLMs + CLI is a natural fit

💬
Text in, text out

LLMs communicate in text. CLI commands are text. No UI to parse, no pixels to interpret — just strings.

🔗
Composable by design

Commands can be piped, chained, and scripted. Agents build workflows by combining simple primitives.

🌐
Universal coverage

git, npm, docker, AWS, databases, file systems — everything has a CLI. One interface to rule them all.

⚡
Faster than GUIs for agents

No rendering, no waiting for pages to load. A CLI command returns a result in milliseconds — critical for tight agent loops.

What prompts actually look like

Chat prompt
Role: You are a senior UX reviewer Task: Critique this onboarding flow for drop-off risks Context: B2B SaaS · mobile · 5 steps · 40% drop at step 3 Format: Bullet list · severity labels

You write the full brief. Claude responds once.

Agent prompt

You state the outcome. The agent breaks it into steps — search, read, compare, write — autonomously.

The more autonomous the agent, the more important a clear goal is. Vague goal → random direction.

AI Agents — Advanced

Why use subagents?

⚡
Parallel execution

Multiple subagents work simultaneously. A 3-task job takes the time of 1, not 3.

🧹
Context isolation

Each subagent starts with a fresh, focused context. The main agent never gets bloated.

🎯
Specialisation

Each subagent is briefed for exactly one task — focused context produces better results.

📏
Breaks context limits

Total work can exceed any single context window — subagents handle pieces, summaries flow back.

Analogy: a manager sends 3 specialists to do research simultaneously. Each returns a 1-page summary — far cheaper than one person doing all 3 tasks in sequence.

Part 6 — Context

Context is everything

The model only knows what you tell it.
Every gap in context is filled with a guess.

Vague brief

"Help me design a better onboarding flow"

Result: generic, forgettable

Rich brief

"You are a senior UX reviewer. B2B SaaS for HR teams. 40% drop-off at step 3 on mobile..."

Result: targeted, actionable

Context

Three levers you control

1

Role — who you tell Claude it is

"You are a senior UX reviewer focused on accessibility..."

2

Task + Constraints — the actual ask

The problem, the audience, the medium, the limitations, the success criteria

3

Examples — show what "good" looks like

A before/after, a reference design, a sample output format. The model learns fast from examples.

Designers are already good at this. Personas, briefs, constraints, success criteria — same skill.

Context

The freelancer brief analogy

Claude is the most responsive freelancer you've ever briefed. It will do exactly what you ask — so ask well.

Prompt Template
Role: You are a [senior UX designer / accessibility expert / ...]
Task: [What you want done, specifically]
Context: [Product, audience, constraints, pain points]
Format: [How you want the output — list, table, critique, etc.]

Four lines. Works every time.

Context

The problem with large context

Lean context
22% full
Context window nearly full
91% — degraded performance
  • ✗
    Slower and more expensive — the model processes every token on every request
  • ✗
    Lost in the middle — models lose track of information buried in the middle of very long contexts
  • ✗
    Context cutoff — when the limit is hit, the earliest content gets dropped silently
  • ✗
    Diluted focus — more noise makes it harder for the model to follow your actual intent
Context

How to keep context lean

🗂️
Start fresh for new tasks

Don't carry baggage from an unrelated conversation into a new one

✂️
Summarise, don't paste

Paste a 3-line summary of a document instead of the full 50-page doc

📌
System prompt for permanents

Put stable instructions there once, not re-stated in every message

🔍
Use retrieval, not raw data

Let tools search and fetch only the relevant parts, on demand

🧹
Compact long agent sessions

Ask Claude to summarise the conversation before continuing a long agent run

🎯
Be specific, not verbose

A precise 3-line prompt beats a rambling 20-line one every time

Part 7 — Best Practices

Writing prompts that actually work

5 power techniques

🪜
Think step by step

Add "Before answering, list the key considerations." — better on complex tasks.

🔀
Ask for options, not one answer

"Give me 3 different approaches" — avoids anchoring on the first idea.

🚫
Use negative constraints

"Don't use jargon. Don't exceed 3 bullet points." — bounds the output precisely.

🪞
Ask it to critique itself

"What's weak about this? How would you improve it?" — unlocks a second pass.

🎯
Define success upfront

"A great answer will be under 50 words and include a CTA."

Weak → strong

❌ Weak prompt
"Help me write copy for our app"
✅ Strong prompt
You are a UX writer for B2B SaaS.
Task: Write 3 options for the empty state
on our HR dashboard.
Context: HR managers, no employees added yet.
Tone: warm, action-oriented.
Format: 2 lines + 1 CTA per option.
Example: "Your team is ready when you are."
Don't use the word "empty" or "nothing".

Limitations

What Claude can't do well

  • ✗

  • ✗
    No memory between sessions — each new conversation starts blank unless memory is configured

  • ✗
